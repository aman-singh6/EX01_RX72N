# Ex01_RX72N

RX72N (`R5F572NN`) 向けの、Renesas RX GCC と CMake を使用する CAN 通信講義用プロジェクトです。Smart Configurator が生成する CAN および CMT FIT モジュールを利用し、CAN1 から周期送信します。

## 構成 / Project layout

- `src/`: 講義で編集するアプリケーションコードと Smart Configurator の生成コード
	Application code edited during lectures and Smart Configurator generated code
- `.vscode/launch.json`: E2/JTAG による VS Code 用ハードウェアデバッグ設定
	VS Code hardware-debug configuration for E2/JTAG
- `CMakeLists.txt`, `cross.cmake`: RX GCC 向けビルド設定
	Build configuration for RX GCC
- `build/`: CMake の生成物。Git 管理の対象外
	CMake output, excluded from Git

## 講義で編集する範囲 / Files to edit in lectures

通常の演習では `src/Ex01_RX72N.c` を編集します。レジスタを直接操作する記述および FIT API の利用は、RX の GPIO と周辺機能を理解する講義用の方針です。ドライバ層への追加抽象化は行いません。
For normal exercises, edit `src/Ex01_RX72N.c`. Direct register access and FIT API usage are intentional for learning the RX GPIO and peripheral functions. Do not add another driver abstraction layer.

`src/smc_gen/` は Smart Configurator の生成コードです。設定を変更する場合を除き、通常の演習では編集しません。`src/linker_script.ld` はデバッグ時にオプション設定メモリ (OFS) をダウンロード対象から除外します。
`src/smc_gen/` contains code generated by Smart Configurator and should not be edited during normal exercises unless changing the configuration. `src/linker_script.ld` excludes the option-setting memory (OFS) from debug downloads.

## ビルドとデバッグ / Build and debug

VS Code で開き、`Build Project` を実行します。初回ビルド時に `build/` が生成されます。
Open the project in VS Code and run `Build Project`. The first build creates `build/`.

デバッグ構成 `Debug (E2 / JTAG)` はビルド後に `build/Ex01_RX72N.elf` を E2 経由で実行します。E2 からターゲットへ給電しないため、デバッグ前に対象基板を外部から給電してください。
The `Debug (E2 / JTAG)` configuration runs `build/Ex01_RX72N.elf` through the E2 after building. The E2 does not power the target, so power the target board externally before debugging.

## CANalyzer による動作確認 / Verification with CANalyzer

CAN通信の動作確認には Vector CANalyzer を使用します。CANalyzerで `Ex01_RX72N.cfg` を開き、プロジェクトに含まれる `Ex01_RX72N.dbc` をデータベースとして使用してください。DBCには、プログラムが送信するCAN ID `0x100`、`0x101`、`0x102` と、対応する信号が定義されています。
Use Vector CANalyzer to verify CAN communication. Open `Ex01_RX72N.cfg` in CANalyzer and use the included `Ex01_RX72N.dbc` as the database. The DBC defines CAN IDs `0x100`, `0x101`, and `0x102`, together with the signals transmitted by the program.

CANalyzerを起動する前に、対象基板へ電源を接続し、CANalyzerとRX72N基板をCANバスへ接続してください。CANalyzerの測定開始後、周期送信される信号をトレースまたはグラフィックで確認します。
Before starting CANalyzer, power the target board and connect CANalyzer and the RX72N board to the CAN bus. After starting the measurement, check the periodically transmitted signals in the Trace or Graphics window.

## Git 管理対象 / Git scope

VS Code 運用では `.project`、`.cproject`、`.settings/`、`.metadata/`、`build/`、`output/`、`trash/` は Git 管理から除外します。CANalyzerで使用する `Ex01_RX72N.cfg` と `Ex01_RX72N.dbc` は動作確認に必要なため、Gitで管理します。
For the VS Code workflow, `.project`, `.cproject`, `.settings/`, `.metadata/`, `build/`, `output/`, and `trash/` are excluded from Git. `Ex01_RX72N.cfg` and `Ex01_RX72N.dbc` are required for CANalyzer verification and are therefore tracked in Git.
